# 补天平台规范化提交漏洞须知(官方模板)

> 来源: https://www.butian.net/Article/content/id/543 (补天官方公告, 2025-10-16)
> 抓取整理: 2026-10-12 (正文 + 官方截图 OCR 还原)
>
> 官方原文: 白帽子需尽可能清晰地描述漏洞细节,提交后积极支持厂商重现和修复,
> **请务必依照模板规范化提交漏洞,以避免影响审核结果**。
> 按此规范标准提交的 SQL 注入漏洞可获得**优先审核权益**。

---

## 一、公益SRC 提交模板(通用字段)

以 SQL 注入为例,完整字段如下(其他漏洞类型同样适用):

### 1. 漏洞 URL
- URL 格式:**以 `http://` 或 `https://` 开头**
- **GET 类型**注入:在此提交**带注入参数的完整 URL**
- 可用「+添加URL」追加多个 URL
- 注入类型为 **POST** 时需要写三处:
  1. 基本 URL
  2. 完整注入数据包(完整 HTTP 请求包)
  3. 注入参数名

官方示例(SQL 注入,POST):
```
1. 基本URL:
http://x.x.x.x/sqli-labs/Less-11/

2. 完整注入数据包:
POST /sqli-labs/Less-11/ HTTP/1.1
Host: x.x.xx
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) ...
uname=admin&passwd=admin&submit=Submit

3. 注入参数:
uname
```

### 2. 漏洞类型
- 大类:**事件型** / 通用(第三方软件漏洞)
- 具体类型:如 SQL 注入、XSS、Shiro 反序列化、命令执行等

### 3. 归属证明
- 提供目标属于该厂商的证据,例如**百度搜索目标站点的结果截图**
  (证明域名/网站归属)

### 4. 首页截图
- **必须包含地址栏**(证明访问的 URL)

### 5. 漏洞证明
- 截图需体现漏洞成立,例如:
  - RCE:执行 `whoami` 的输出(`nt authority\system`)
  - 标题式结论:「http://106.x.x.x:8080/a/login 存在 shiro 反序列化漏洞」+ 回显截图

### 6. 漏洞权重(公益和未注册厂商**必选**,选错/漏选将驳回!)
- 以**主域名的爱站权重**为准:
  - 百度/百度移动权重 ≥1 **或** 谷歌权重 ≥3 → 选 **权重 ≥1**
  - 否则 → 选 **权重 = 0**
- 权重为 0 的厂商务必选「权重=0」

### 7. 活动/任务选择
- **如未选择活动,默认不参与奖励计划**(请在个人中心及时检查遗漏)
- 活动:活动中心报名,报名前详细阅读活动规则
- 任务:个人空间点击领取,领取前详细阅读任务规则
- 活动与任务为**额外奖励**,不影响漏洞本身奖励

### 8. 漏洞等级
- 低危 / 中危 / 高危(按实际影响如实选择)

### 9. 漏洞详情(必填,决定审核成败的核心字段)
要求:
- 漏洞利用的**完整过程**:相关 URL、截图、代码以及 POC
- **准确描述漏洞存在的功能点 + 到达该功能点的完整步骤,并截图**
  - 例:「漏洞位置:登录 xx 网站 → /app → 小程序 → 个人信息 → 收货地址」
- **详细的利用过程、POC、必要的数据包**(POC 和关键数据包必须放在**代码块**中)
- **需要登录的,必须提供测试账号**
- **必须附两张证明截图(本地上传,勿复制粘贴),缺失可能被驳回:**
  1. **漏洞完整复现过程截图**: 浏览器 F12→Network(Preserve log)按 POC 逐步触发,
     截含地址栏 + 关键请求(红色失败项/异常回显)的多步过程;curl 复现则截 `-v` 输出
  2. **厂商归属证明截图**: 百度搜索厂商全称的结果页(第一结果为官网,主域与漏洞URL一致),
     或官网首页(含地址栏,标题/Logo 对应厂商名称)
- 若不符合规则,漏洞可能审核不通过

IoT 漏洞额外要求:
1. 漏洞触发对应的**二进制位置**
2. **目标配置情况**
3. **漏洞研究环境**:真实硬件 → 提供购买链接;模拟仿真 → 描述环境搭建与调试方法

利用过程中用到**组件**的:提供下载链接,或压缩后以附件上传。

### 10. 附件
- 正常情况下,**所有漏洞细节都应在「漏洞详情」栏中体现**
- 仅视频或过长的 payload 才以附件形式提交
- 只支持**压缩后的文件/图片/视频:仅 zip/rar,且 ≤50M**

### 11. 修复方案
- 提供**具体**的修复方案(例:「随机生成密钥,不要使用公开的密钥」)
- 请勿以 `11111111`、「无无无」等敷衍填写

### 12. 所属行业 / 行业分类
- 根据厂商经营方向选择,需**精确到厂商具体经营内容**
- 分类示例:IT/计算机软件/硬件/服务、互联网/增值服务、电子商务/网络/游戏/电子技术、
  工业自动化、智能硬件、通信技术、房产服务/中介、水务/建筑/装修、房地产开发等

### 13. 所属地区
- 填写**厂商的位置**(而非 IP 定位)

### 14. 厂商联系方式 + 协议勾选
- 平台不会公开白帽子细节(显示为「带头大哥」)
- 勾选同意《用户服务协议》和《用户隐私政策》后提交

## 二、专属SRC 提交模板

在公益模板基础上,额外字段:

- **厂商名称**(如:xx厂商)
- **厂商测试范围**:域名或 IP(如 `www.test.com`)
- 其余字段(漏洞URL/类型/等级/详情/附件/修复方案)与公益模板一致
- 专属SRC漏洞信息**不公开**

## 三、提交前自查清单(按此打勾再提交)

- [ ] URL 以 http(s):// 开头,GET 注入带完整参数
- [ ] POST 注入:基本URL + 完整数据包 + 参数名 三处齐全
- [ ] **简要描述**已填:漏洞概述+影响,一两句话,不含详细URL
- [ ] **① 漏洞完整复现过程截图**已附(本地上传,勿复制粘贴)
- [ ] **② 厂商归属证明截图**已附(本地上传,勿复制粘贴)
- [ ] 首页截图**含地址栏**
- [ ] **权重**按主域名爱站权重正确选择(公益/未注册厂商必选)
- [ ] 活动/任务已按实际选择(不选 = 不参与奖励)
- [ ] 漏洞等级如实
- [ ] 详情:功能点+步骤+截图+利用过程+POC(代码块)+测试账号(如需登录)
- [ ] **小白复现手册**已写:点击级步骤+每步预期现象+常见错误操作(自己照做能复现才算数)
- [ ] IoT:二进制位置/配置/研究环境 三项齐全
- [ ] 附件仅 zip/rar ≤50M(能写进详情的就写详情)
- [ ] 修复方案具体、不敷衍
- [ ] 行业/地区/联系方式准确

## 四、审核相关(来自官方 FAQ,详见 butian-faq.md)

- 公益SRC:审核通过后 ~7 天等厂商认领,认领后 1-2 个工作日确认
- 专属SRC:平台 ~1 个工作日审核 + 厂商一周内复审,超期自动通过,奖金确认后 ~7 个工作日到账
- 重复漏洞:以**提交时间**排序
- 驳回原因:官网 个人中心 → 漏洞列表 查看审核意见
- 信誉分:刷洞/一洞多投 -10(专属SRC -20),≤60 封号
